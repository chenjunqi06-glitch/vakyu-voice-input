# 全局语音的 TSF 回投

全局语音默认仍由一个后台线程持有麦克风。标准 Edit / RichEdit 使用原来的焦点校验和 Unicode 输入；其他控件优先尝试当前 Miracle TSF 文档的编辑接口，解决微信等自绘输入区不提供完整 UIA 编辑能力时被拒绝的问题。

协议 v8 在 `InputSettings.voice_delivery` 广告回投能力。它和 `voice_input` 独立：全局后台已接管录音时，DLL 的 `voice_input` 仍为 false，因此不会重复启动录音。新版 DLL 在现有约 320 ms 状态同步节拍发送 `VoiceDeliveryPoll`（宿主 PID/TID 和上次事务状态）。录音/跟读持有已就绪锚点期间仍是 320 ms；只有捕获和提交待确认期间复用 80 ms 定时器处理异步编辑会话，不新增线程或定时器。

Server 的共享 `DeliveryBridge` 只选取两秒内活跃、PID/TID 匹配的会话。一次录音取得 `Capture` 事务后，DLL 经异步只读编辑会话保存空 `VoiceAnchor`，拒绝私密/只读输入框；无匹配客户端或900 ms 内未确认时使用已有 UIA 检测路径，宿主明确拒绝捕获则不回退，防止私密判定被 UIA 降级绕过。捕获只查输入属性，不读取光标前文。捕获成功后录音和跟读期间均持有该锚点。焦点变化不会把结果投给别的输入框。

完成识别或跟读后，`Commit` 把中文交给同一锚点，提交前再次检查只读/私密状态，调用 `ITfInsertAtSelection` 并报告 `Inserted`。文本不经剪贴板，不按 Enter，不自动发消息。编辑回调遵守 1500 ms 截止，后台最多等待 1900 ms。捕获时没取得 TSF 锚点可以走原 UIA 路径；一旦锁定 TSF 锚点，提交被拒绝也不能跨路线改用 SendInput，避免同一 HWND 中焦点已移动到另一个自绘输入区。ACK 丢失或超时提示检查输入框，重复尝试仍保持未确认，不重复写入。断连、停用或票据销毁撤销事务；提交途中断连保持未确认而不是安全拒绝，迟到响应不复活旧事务。

兼容性：`VoiceDelivery` 新枚举只回应 v8 新消息，旧 DLL 不收到新变体，仍使用原来的全局语音路径。新 DLL 的回投能力缺省关闭，不给旧 Server 发新消息。安装后已经运行的软件可能仍映射旧 DLL；必须确认当前宿主已加载新版，单纯替换磁盘上的 DLL 不能让已映射的机器码改变。

验证：broker 单测覆盖宿主身份绑定、确认后成功、断连撤销；内存双工协议单测覆盖 PID/TID、请求号和 ACK 不串包。真实微信验收需点击聊天输入区，按语音键说话松开，核对自动填入且未发送；随后测试跟读完成、Esc 取消、录音中切换聊天窗口、密码/只读区拒绝，以及浏览器和记事本原有路径。

交付诊断只记录 sequence、目标 PID/TID、投递方式与错误类型，不记录正文。`tsf` 成功表示宿主报告了插入；`native_unicode` / `uia_unicode` 成功仅表示系统接收了按键事件，不能据此宣称目标正文已填入。微信当前进程仍映射旧 DLL 时，应先确认实际加载版本，再验证新接口，避免反复重装相同文件。
